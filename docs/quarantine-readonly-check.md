# 隔离历史的只读核对

本工具用于客服核对已完成的 `history-conflicts` 批次。它不恢复文件，不打开数据库，不读取账号凭据，不结束进程，也不发起网络请求。唯一写入是在桌面新建一份 `GuardianHistoryCheck-日期时间.json` 结果。

## 使用

1. 从经过云端验收的固定提交下载 `tools/inspect-history-quarantine.ps1`。
2. 用记事本打开该文件，复制全部内容；从开始菜单打开 Windows PowerShell，粘贴并回车。
3. 提示 `Paste the full Guardian quarantine folder path` 时，粘贴客服已经核对过的隔离批次文件夹完整路径。
4. 将桌面新生成的 `GuardianHistoryCheck-*.json` 发给正在协助的客服。若没有生成，提供最后的错误信息。无需管理员权限。

工具核对隔离清单和对应完整冷备清单的关联，对隔离批次每个历史文件分别计算隔离副本、冷备副本与原路径现存文件的 SHA-256，读取有限大小的 session_meta，仅输出历史 ID、模式、依赖编号和字节偏移。也检查清单中同组其他原路径文件。结果不包含聊天正文、系统指令、账号凭据或 provider 配置。

清单的 SQLite integrity 只是备份时记录；工具不会重新打开数据库验证。它也未扫描清单生成后的新历史文件，所以结果始终标记 `restore_ready=false`。即使校验一致，也不能将此结果当成会话已恢复或全链路健康。

路径越界、重复记录、未完成冷备、重解析点会被拒绝。现存文件不覆盖、不移动；已存在的报告同样不覆盖。实际恢复必须另行形成明确方案、完成必要冷备和隔离验证，并在客户确认后执行。
